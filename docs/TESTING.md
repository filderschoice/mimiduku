# テスト手順

## 1. 単体テスト

```sh
./gradlew testGithubDebugUnitTest testPlayDebugUnitTest
```

判定ロジックは Android 非依存のクラスに置き、単体テストで確認しています。

| テスト | 確認内容 |
| --- | --- |
| `RulesLoaderTest` | 同梱の `rules.json` と既定ルールの一致、壊れた JSON・未対応の版のときの既定値への切り替え |
| `ScarewareMatcherTest` | 日英の文言、全角半角・大文字小文字・空白の吸収、ノードをまたいだ文言 |
| `ExternalTransitionDetectorTest` | アプリ→ブラウザ/ストア/インストーラー、ランチャー・設定・ブラウザ同士の除外、繰り返し回数 |
| `DetectionLogTest` | 追記・件数上限・破損ファイルからの復帰、画面の文字を保存しないこと |
| `UsageModeTest` | 利用モードの保存、モード別の介入内容（自動で戻す回数の上限を含む） |
| `ProtectionEngineTest` | イベントの変換、検知から介入・ログ・バナー内容まで、スケアウェア照合の間引き |
| `InterventionPlannerTest` | 検知ごとの介入の内容（ログのみ・ドメイン待ち・戻る操作と「今後は確認しない」の有無）、版による違い |
| `SetupStatusTest` | アクセシビリティの有効判定、制限された設定の案内を出す OS 版 |
| `PinManagerTest` | PIN の設定・照合・形式、連続失敗の待ち時間、平文を保存しないこと、保存値の破損 |
| `PinPolicyTest` | どの操作で PIN を求めるか、照合結果の文言 |
| `PauseStoreTest` | 一時停止の期限・時刻の巻き戻し・再起動後の保持・破損した保存値 |
| `SettingsControllerTest` | 設定画面の操作の流れ（画面間の移動、PIN の要求、モード切替、一時停止、ログの閲覧と消去、バッジ） |
| `AdScreenDetectorTest` | 広告 SDK の Activity 名と文言の重みによる広告画面の判定 |
| `CountdownParserTest` | 残り秒数の読み取り、案内パネルの文言 |
| `ShieldTimerTest` | タップシールドを張る条件と60秒の上限 |
| `CloseButtonFinderTest` | 代理タップする閉じるボタンの選び方 |
| `BadgeExpressionTest` | バッジの表情と表示設定 |
| `BadgePlacementTest` | バッジの吸着・最小化の判定、縦向き・横向きでの座標、保存と壊れた値 |
| `FeatureSetTest` | 版ごとの機能の組、Play 版での介入（タップのあった遷移を対象にしない、こどもモードでも確認を出す）と文言 |

## 2. 実機での確認（人手検証 BL-009）

自動化できないため、人が実機で確認します。結果は「4. 記録欄」に書き、BACKLOG の BL-009 の完了判定に使います。

### 2.1 注意事項

- **実際の広告はクリックしないでください。** 広告のクリックや完了の偽装はクリック詐欺に当たるため、
  本手順では adb やメモアプリで同じ状況を再現します。
- 端末は可能なら Android 10・13・14 以降の3世代、ジェスチャーナビと3ボタンナビの両方で確認します。

### 2.2 準備

1. README の「インストール」の手順で debug 版を入れ、アクセシビリティをオンにします。
2. アプリを開き、「見張っています」と表示されることを確認します。

### 2.3 確認項目

| No | 手順 | 期待する結果 |
| --- | --- | --- |
| T1 | こどもモードで、電卓など任意のアプリを前面に出し、PC から `adb shell am start -a android.intent.action.VIEW -d https://example.com` を実行 | ブラウザが開いた直後に元のアプリへ戻り、「みみづくが止めたよ」のバナーが出る |
| T2 | T1 と同じ操作で、`-d "market://details?id=com.android.chrome"` を実行 | Play ストアが開いた直後に戻り、バナーが出る |
| T3 | T1 を30秒以内に4回繰り返す | 4回目は戻らず、「ほー、あやしいリンクだよ」のバナーだけが出る |
| T4 | ホーム画面からブラウザのアイコンをタップして開く | 戻らず、バナーも出ない |
| T5 | おとなモードに切り替えて T1 を実行 | 自動では戻らず、「ブラウザへの移動を検知しました」と「戻る」「このまま進む」が出る |
| T6 | T5 のバナーで「戻る」を押す | 元のアプリへ戻る |
| T7 | T5 のバナーで「このまま進む」を押す | バナーが消え、ブラウザのまま操作できる |
| T8 | メモアプリなどに「お使いの端末はウイルスに感染しています」と入力する | 警告バナー（こども：「みみづくが気づいたよ」、おとな：「偽の警告の可能性があります」）が出る |
| T9 | ブラウザで「Your device is infected」を含むページを開く（検索結果やテスト用の自作ページ） | 警告バナーが出る。Web ページ内の文字が読めない場合は結果に記録する |
| T10 | T8 の直後、同じ画面のまま操作を続ける | 60秒間は同じ警告が繰り返し出ない |
| T11 | バナーが出ている間に、バナーの外をタップする | 下のアプリが操作できる（バナーがタップを吸収しない） |
| T12 | ジェスチャーナビの端末で T1 を実行 | 3ボタンナビと同じく戻る |
| T13 | Android 13 以降で、ブラウザやファイルマネージャーから APK を入れてアクセシビリティをオンにする | ホームの「オンにできないとき」の手順でオンにできる |
| T14 | ホームの「検知ログ」の件数 | 上記の検知回数だけ増えている |
| T15 | 端末を再起動する | 再起動後もアクセシビリティがオンのままで、T1 が再現する |

### 2.4 第2段階の確認項目（人手検証 BL-023）

広告画面の確認には、広告 SDK のテスト広告を出すアプリ（例：Google Mobile Ads のサンプルアプリをテスト用の広告ユニット ID で
ビルドしたもの）を使い、**本番の広告はクリックしないでください。**

| No | 手順 | 期待する結果 |
| --- | --- | --- |
| P1 | 右上の歯車から設定を開き PIN を設定し、おとなモードへ切り替える | PIN の入力を求められ、正しい PIN で切り替わる |
| P2 | 違う PIN を5回入力する | 5回目の後、しばらく入力できない旨が出る。30秒後に正しい PIN で通る |
| P3 | おとな→こどもへ切り替える | PIN を求められずに切り替わる |
| P4 | 15分の一時停止を PIN つきで行い、T1 を実行する | 戻らず、バナーも出ず、バッジも消える。「今すぐ再開する」で元に戻る |
| P5 | 「ログを見る」で一覧を開き、消去する | 新しい順に並び、消去に PIN を求められる |
| P6 | テスト用のインタースティシャル広告を表示する（こどもモード） | 画面下部に「こうこくだよ。さわらないでね。」と残り秒数・「もどる」が出て、広告部分はタップできない |
| P7 | P6 のまま60秒待つ | シールドが外れ、広告に触れるようになる（案内パネルは残る） |
| P8 | P6 で「もどる」を押す | 閉じる・スキップボタンが出ていれば押されて広告が閉じる。出ていなければ戻る操作になる |
| P9 | おとなモードで P6 を行う | シールドは出ず、案内パネルだけが出る |
| P10 | バッジを確認する（平常・広告画面・T1 の直後） | うとうと → 耳が立つ → 目が大きい、と変わる。バッジの外側のタップは下のアプリへ届く（バッジ自体のタップは「×」の表示。BL-054） |
| P11 | 設定画面（歯車）でバッジを非表示にする | 次の操作でバッジが消える |
| P12 | ホーム画面のアイコンを確認する | みみづくのアイコンになっている |

### 2.7 バッジの移動・最小化・通知の確認項目（人手検証 BL-043）

縦向きと横向きの両方で確かめます。Android 13 以降の端末では、通知の許可ダイアログも確かめます。

| No | 手順 | 期待する結果 |
| --- | --- | --- |
| B1 | バッジを指でドラッグして画面の中央付近で離す | 近い方の左右どちらかの端へ吸着する。ドラッグ中にバッジが元の位置へ戻らない |
| B2 | バッジを画面の外（端の外側）へ半分以上引き出して離す | 端から約32dpだけが見える半透明の表示になる |
| B3 | 最小化したバッジを、上下に動かす・内側へ引き出す・タップする | 上下は最小化のまま動き、内側へ十分に引き出すと通常の表示に戻り、タップでも戻る。のぞいている部分は指でつかめる |
| B4 | 端末を横向きにして B1〜B3、縦向きへ戻す | 縦位置が割合で保たれ、画面の端に合う（画面外へ出たり中央に残ったりしない）。向きを戻しても位置が自然に戻る |
| B5 | バッジを動かしてから端末を再起動する | 位置と最小化の状態が保たれている |
| B6 | 通知の「バッジを隠す」を押し、続けて「バッジを出す」を押す | アプリを開かずに切り替わり、通知のボタンの文言も入れ替わる。設定画面のスイッチと一致する |
| B7 | 設定画面で通知のスイッチをオフ→オン、Android 13 以降は許可を拒否する | オンにしたとき許可を求められる。拒否すると通知は出ないが、バッジと検知は動く。オフで通知が消える |
| B8 | 一時停止中、または同意前に通知を確認する | 一時停止中はバッジが消える（通知のボタンで出しても表示されない）。同意前は通知が出ない |

### 2.8 ログの確認（任意）

debug 版はログファイルを adb で読めます。画面の文字や URL が含まれていないことを確認します（確認を省いた検知は
`SKIPPED_EXCLUDED` で残りますが、サイト名は含まれません）。

```sh
adb shell run-as com.mimiduku.mobile.full.debug cat files/detection-log.json
```

### 2.9 確認を省く対象の確認項目（人手検証 BL-056）

大人モードに切り替え、保護者 PIN を設定した状態で確かめます。ブラウザは Chrome に加えて、Firefox や Samsung Internet
など、端末にあるものも試します。

| No | 手順 | 期待する結果 |
| --- | --- | --- |
| X1 | 広告のあるアプリからブラウザが開くまで操作し、確認バナーの「今後は確認しない」を押す | 本体の設定画面が開き、アプリ名と（読めたとき）サイト名が選べるダイアログが出る |
| X2 | アプリを選んで「登録する」を押す。PIN を設定していない場合は先に設定する | PIN の入力を求められ、成功すると「確認を省く対象」にアプリ名が並ぶ。PIN 未設定のときは登録されず PIN の設定が求められる |
| X3 | 同じアプリからもう一度ブラウザを開く | 確認バナーが出ない。検知ログに「登録済みのため確認なし」が残る |
| X4 | こどもモード（GitHub 版）に切り替えて同じ操作をする | 自動で戻る（確認を省く対象があっても介入は変わらない） |
| X5 | サイトを選んで登録し、別のアプリから同じサイトを開く | 開いて約1秒後も確認バナーが出ない（アドレスバーが読めたブラウザ）。別のサイトでは出る |
| X6 | アドレスバーを読めないブラウザで X5 を行う | 確認バナーが出る（確認を省かない）。バナーには「今後は確認しない」が出るが、サイトは読み取れず選べない |
| X7 | 「確認を省く対象」で、アプリを「外す」、サイトを「すべて外す」を押す | PIN なしで外れ、再び確認バナーが出る |
| X8 | ストアやインストーラーが開く遷移を、登録済みのアプリから起こす | ストアは省かれる。インストーラーは登録済みのアプリでも確認バナーが出る |
| X9 | アドレスバーに検索語を入れて開く、別タブ・前のページのドメインを開いたままにする | 検索語は登録の候補にならない。前のページが登録済みのサイトだった場合に、別のサイトへの遷移を誤って省かない（誤って省く場合は BL に起票する） |
| X10 | バナーの「今後は確認しない」を押す（バックグラウンドからアプリが開く） | 本体の設定画面が前面に出る（Android 17 を含め、起動が阻止されないこと） |
| X11 | サイトを登録したあと、「確認を省く対象」の「サイトの一覧を見る（PIN）」を押して PIN を入力する | 登録したサイト名の一覧が出る。間違った PIN では出ない。一覧から「外す」で個別に外れ、そのサイトは確認が出るようになる |
| X12 | PIN を変更して（現在の PIN → 新しい PIN）、新しい PIN で一覧を開く | 新しい PIN で同じ一覧が出る（旧い PIN では開けない） |
| X13 | PIN を削除する | 登録済みのサイトがすべて消える（「確認を省く対象」に表示されない） |
