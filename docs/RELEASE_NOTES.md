# リリースノート

みみづくのバージョンごとの変更点を、アプリの利用者（保護者）向けに記録します。

## このファイルの位置づけ

| ファイル | 対象読者 | 記録する内容 |
| --- | --- | --- |
| 本ファイル（`docs/RELEASE_NOTES.md`） | アプリの利用者 | 配布したバージョンごとの新機能・改善・修正・既知の問題 |
| [CHANGELOG.md](../CHANGELOG.md) | 開発者・メンテナー | リポジトリの運用ルール・ドキュメント・ガードレールの変更履歴 |
| [docs/records/managed/EXECUTE.md](records/managed/EXECUTE.md) | 開発者・AIエージェント | コード修正1件ごとの実施記録（変更ファイル・検証結果を含む） |

## 運用ルール

- 新しいバージョンを先頭に追加します（新着順）。
- 見出しは `## <バージョン>（<リリース日>）` の形式とします。未リリースのものは日付の代わりに「未リリース」と書きます。
- 各バージョンは「新機能」「改善」「修正」「既知の問題」の小見出しで整理します。該当が無い項目は省きます。
- 利用者が読んで分かる言葉で書きます（クラス名・タスクの id などの内部の名前は使いません）。
- GitHub 版と Play 版で違う点は、どちらの版の話かを書き分けます。
- バージョン番号は `scripts/version.properties` の `VERSION_NAME` と一致させます。リリースビルドの手順は
  [README.md](../README.md)「リリースビルド」を参照してください。
- `scripts/version.properties` の記録は `VERSION_CODE=1` から始まるため、`scripts\release-build.bat` を引数なしで実行すると
  最初の配布の versionCode は 2 になります。1 にしたい場合は、初回だけ `-VersionCode 1` を指定します。
- 署名の鍵の場所（`local.properties` の `RELEASE_STORE_FILE`）を相対パスで書いた場合は、リポジトリの直下を基準に解決します。
- Google Play Console の「このリリースの新機能」欄は500文字以内です。Play 版を配布するバージョンには、そのまま転記できる
  「ストア掲載用の要約」を用意します。
- GitHub Releases を作成する場合も、本ファイルの該当バージョンの内容を本文へ転記します。

## 0.1.0（2026-11-25）

Play 版の内部テスト（Google Play Console）で最初に配布したバージョンです（versionCode 4）。

### 新機能

- 広告によくある偽の警告（「ウイルスに感染しています」など）に気づいて、「偽の警告の可能性があります」と知らせます。
- アプリを使っている最中に、タップしていないのにブラウザや Play ストアが開いたときに知らせ、「戻る」か「このまま進む」を選べます。
- 保護者 PIN で、設定の切り替えや一時停止を守れます。
- 検知の記録（いつ、どのアプリで何に気づいたか）を、端末の中で確認できます。

### 既知の問題

- 広告を消したりブロックしたりはしません。通常の広告の表示やクリックには介入しません。

### ストア掲載用の要約

Play Console の「このリリースの新機能」欄（500文字以内）へ、そのまま転記する文面です。

```text
<ja-JP>
みみづく 0.1.0（内部テスト版）

初めてのテスト版です。
・偽の警告（「ウイルスに感染しています」など）に気づいて知らせます
・タップしていないのにブラウザや Play ストアが開いたときに知らせ、「戻る」か「このまま進む」を選べます
・保護者 PIN で、設定の変更や一時停止を守れます
・検知の記録を、端末の中で確認できます

ご確認いただきたい点：
・最初の起動時の説明と同意の流れが分かりやすいか
・偽の警告や勝手な移動の通知が、気になる頻度で出ていないか

広告の表示を消したりブロックしたりはしません。情報は端末の外へ送りません。
</ja-JP>
```
