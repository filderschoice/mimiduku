# 配布の構成案（Google Play 版と GitHub 版）

BACKLOG の BL-026 の成果物です。配布の方針を決める BL-024 の判断材料として、Google Play のポリシーと
mimiduku の各機能の関係を整理し、構成案を比較します。

- 調査日: 2026-10-19
- 一次情報: Google Play Console ヘルプ・Android Developers（URL は 7章）
- 本書の記述はポリシー本文の読み取りに基づく見立てです。**Google の審査結果を保証するものではありません。**
  確かめきれなかった点は 6章に「未確認」としてまとめています。

## 1. 前提：対象は悪質な広告であり、通常の広告には介入しない

mimiduku の目的は、**悪質な広告**（偽の警告、勝手な外部遷移、偽の閉じるボタン、不正なインストールへの誘導など）から
利用者を守ることです。通常の広告の表示・クリック・収益に介入することは目的に含みません（2026-10-19 のユーザー指示）。

この前提で各機能を見直すと、介入のきっかけは次の2種類に分かれます。

| きっかけ | 例 | 前提との関係 |
| --- | --- | --- |
| **悪質さのシグナル** | 偽の警告の文言、タップなしの自動外部遷移、ストア・インストーラーへの勝手な誘導 | 前提どおり |
| **広告であること自体** | 広告 SDK の画面、「スキップ」「報酬を獲得」の表示 | 通常の広告にも反応するため、前提から外れる |

現在の実装では、広告画面の案内パネル（BL-019）・タップシールド（BL-020）・閉じるボタンの代理タップ（BL-021）・
バッジの「耳が立つ」表情（BL-022）が後者の「広告であること自体」をきっかけにしています。

**GitHub 版での扱い（2026-10-19 にユーザーが決定）**: 全画面広告で作動するのは今のままでよい。正常な広告に見えても
悪質な場合がありうるため、GitHub 版では全画面広告への介入（案内パネル・こどもモードのシールド・代理タップ）を残す。
この線引きは Play 版にだけ適用する（4章の案 C）。

## 2. 関係する Google Play のポリシー

| ポリシー | 要点（本文の読み取り） | mimiduku への影響 |
| --- | --- | --- |
| デバイスとネットワークの不正使用 | 他のアプリへの干渉を禁止する。よくある違反の例に「他のアプリの広告表示をブロック・妨害するアプリ」がある。保護者向けアプリ・セキュリティアプリへの例外は書かれていない | **最大の論点。** 広告画面への介入（シールド・代理タップ・案内パネル）はこれに当たる可能性が高い |
| AccessibilityService API の利用 | 支援技術（障害のある人の支援が主目的）以外のアプリも使えるが、アプリ内の目立つ開示と、利用者の能動的な同意（タップ・チェック）が必須。Play Console での申告と、開示を映した動画の提出が必要。セキュリティ・監視・自動化のアプリは支援技術に当たらない例として挙がっている | 対応すれば利用できる。`isAccessibilityTool` は宣言できない |
| 同上：自律的な操作の禁止 | API を使って自律的に行動を計画・実行することは禁止。ただし人が決めた固定の規則に従う決定的な自動化は禁止の対象外 | mimiduku の介入は固定の規則によるため、この禁止には当たらない見込み |
| isMonitoringTool の申告（ストーカーウェア） | 他人の個人データを**収集して送信する**監視アプリは申告が必要（保護者向けは `child_monitoring`） | mimiduku は端末内にログを残すだけで送信しないため、対象外の可能性が高い（未確認） |
| Android 開発者認証（Play 外の配布） | 認証済み（certified）の端末では、2026-09-30 から一部の国（ブラジル・インドネシア・シンガポール・タイ）で、2027年以降は全世界で、登録された開発者のアプリでないとインストールできなくなる。adb でのインストールと、上級者向けの「advanced flow」は例外。学生・趣味向けの「限定配布アカウント」は端末20台まで、身分証も登録料も不要 | GitHub 版・サイドロード版にも影響する。家庭内の数台なら、限定配布アカウントか adb で足りる |

## 3. 機能ごとの評価

凡例：○ Play 版に入れられる見込み ／ △ 審査で問題にされうる（形を変えれば入れられる余地あり） ／ ✕ Play 版には入れない

| 機能 | きっかけ | 該当するポリシー | Play 版 | 理由 |
| --- | --- | --- | --- | --- |
| スケアウェア文言の警告 | 悪質さのシグナル | 広告の妨害 | ○ | 広告の表示は止めず、文言について利用者へ知らせるだけ |
| 外部遷移の検知（**タップなし**の自動遷移）→ 確認を出す | 悪質さのシグナル | 広告の妨害 | ○ | 広告の表示ではなく、利用者が意図していない遷移の結果に対処する。おとなモードと同じ「戻る／このまま進む」の確認形式なら干渉が最小 |
| 外部遷移の検知（タップなし）→ **自動で戻る** | 悪質さのシグナル | 広告の妨害 | △ | 悪質な挙動への対処ではあるが、確認なしに戻すのは干渉とみなされうる |
| 外部遷移の検知（**タップあり**）→ 戻る・確認 | 通常の広告クリックを含む | 広告の妨害 | ✕ | 通常の広告クリックの結果を止めることになり、前提にも反する |
| 広告画面の案内パネル（残り秒数・「さわらないでね」） | 広告であること自体 | 広告の妨害 | ✕〜△ | 広告は覆わないが、通常の広告に毎回重ねて出る。悪質さのシグナルがあるときだけ出す形なら△ |
| 全画面広告のタップシールド | 広告であること自体 | 広告の妨害 | ✕ | 広告への操作そのものを遮る |
| 閉じるボタンの代理タップ | 広告であること自体（利用者の操作が起点） | 広告の妨害 | ✕ | 広告を閉じる操作を代行する。利用者の操作が起点でも、他のアプリの広告への干渉にあたる |
| バッジの表情（広告画面で耳が立つ） | 広告であること自体 | 広告の妨害 | △ | 表示だけで干渉はしないが、Play 版では悪質さのシグナルだけで表情を変えるほうが安全 |
| 保護者 PIN・一時停止・ログ閲覧 | — | — | ○ | 自アプリ内の機能 |
| アクセシビリティ API の利用そのもの | — | AccessibilityService API | ○（作業あり） | 目立つ開示と同意の画面、Play Console の申告と動画、プライバシーポリシーが必要 |

## 4. 構成案の比較

| 案 | 内容 | 子供の保護 | 審査のリスク | 手間 | 前提（通常の広告には介入しない）との整合 |
| --- | --- | --- | --- | --- | --- |
| A. サイドロードのみ（現状） | 全機能。家庭内で adb か APK でインストール | 強い | なし | 小。2027年以降は限定配布アカウントか adb が必要 | シールド等が通常の広告にも働くため、ずれている |
| B. Play 版のみ（機能限定） | 3章の○だけ | 中 | 低〜中 | 中（開示・申告・動画・プライバシーポリシー） | 合う |
| **C. Play 版（機能限定）＋ GitHub 版（全機能）** | Play 版は3章の○、GitHub 版は全機能。同じソースからビルドの種類（product flavor）で出し分ける | Play 版は中、GitHub 版は強い | Play 版は低〜中 | 大（B の作業＋出し分けと2系統のリリース） | Play 版は合う。GitHub 版は全画面広告にも介入する（1章のユーザーの決定） |
| D. 全機能を悪質さのシグナル起点に作り直し、1系統で Play へ | 案内パネル・シールドも、悪質さのシグナルがあるときだけ働かせる | 中〜強 | 中（シールドは△以上にならない見込み） | 大（判定の作り直し） | 合う |

### 推奨：案 C

- 前提（悪質な広告への対応）を Play 版でそのまま形にでき、審査で論点になる機能（シールド・代理タップ・タップあり遷移の介入）は
  Play 版から外せる。
- 子供の端末で強い保護が要る家庭は、GitHub 版を選べる。Play 版でも制限された設定（Android 13 以降）の手順は不要になる。
- Play のリスティングから、Play のポリシーに反する機能を持つ APK（GitHub 版）へリンクしないこと。ストーカーウェア方針の
  「Play 外の非準拠 APK へリンクしない」という趣旨に照らすと、同様の扱いになる可能性がある（未確認）。
  GitHub の README から Play 版へリンクするのは問題ない見込み。

## 5. 案 C を実装する場合の作業

2026-10-19 にユーザーが「ソースは同一、Play 版はフラグで機能を抑止」とする構成を選んだ。ビルドの出し分けと
Play 版の介入の絞り込みは実装済み（BL-028、DESIGN.md の FR-19）。残りは BACKLOG の BL-029〜BL-031。
Play Console への登録・申請は外部への発信のため、人が行います。

| 作業 | 内容 | 担当 |
| --- | --- | --- |
| ビルドの出し分け | `productFlavors` に `play` と `github` を作り、機能の有無を `BuildConfig` の値で切り替える。判定は Android 非依存の `FeatureSet` に置いて単体テストする | エージェント |
| Play 版の介入の絞り込み | 外部遷移は「タップなし」のときだけ確認を出す（自動で戻さない）。案内パネル・シールド・代理タップを外す。バッジの「耳が立つ」は使わない | エージェント |
| 目立つ開示と同意の画面 | アクセシビリティを有効にする前に、読み取る情報（画面の文字）・用途（照合のみ）・保存・送信しないことを示し、同意のチェックとボタンを求める。両方の版に入れる | エージェント |
| プライバシーポリシー | 公開ページ（例：GitHub Pages）を用意する | エージェント（文面）・ユーザー（公開） |
| applicationId と署名 | Play 版は Play App Signing の鍵、GitHub 版は自前の鍵になるため、互いに上書き更新できない。GitHub 版は別の applicationId（例：`com.mimiduku.mobile.full`）にすると、両方を入れても衝突しない | エージェント（設定）・ユーザー（鍵の作成） |
| Play Console の申告 | アクセシビリティの申告フォーム、開示を映した動画、データセーフティ、対象年齢（子供向けアプリとしない） | ユーザー |
| 開発者認証 | GitHub 版は2027年以降の全世界での適用に備えて Android Developer Console で登録するか、限定配布アカウント（20台まで）を使う | ユーザー |
| リスティング | 「悪質な広告への対策」であり、広告ブロッカーではないことを明記する | ユーザー（エージェントが文案） |

## 6. 未確認の点

- 「悪質な広告への対策」という目的が、広告の妨害の禁止に対する例外として扱われるか。本文に例外は書かれていない。
  確かめるには、Play Console からポリシーの事前相談をするか、審査に出してみるしかない。
- タップなしの外部遷移に確認を出すことが「広告の妨害」に当たらないか（3章で○としたのは本文の読み取りによる見立て）。
- 端末内にだけログを残す保護者向けアプリが `isMonitoringTool` の申告の対象か。定義は「収集して送信する」監視で、
  対象外と読めるが明記はない。
- Play のリスティングと GitHub 版の関係（Play 外の APK の存在が審査に影響するか）。
- 子供の端末で使うアプリが、ファミリー ポリシー（子供向けアプリ）の対象にならないか。対象年齢を保護者にする想定だが、本文は確認していない。
- 開発者認証の 2026-08 以降の実施状況（限定配布アカウント・advanced flow が予定どおり始まったか）。確認できた最新の情報は 2026-06 のもの。
