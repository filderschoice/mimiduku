## 1. 前提・制約の確認結果

### 1.1 確定した事項（2026-10-18 のユーザー回答）

| 項目 | 決定 |
| --- | --- |
| UI 方式 | オーバーレイは View、設定画面は Jetpack Compose |
| applicationId | `com.mimiduku.mobile`（sesami-wear の `com.sesamiwear.mobile` に合わせた形。debug 版は `.debug` を付ける） |
| MVP の範囲 | PLAN 8章の実装優先順 1（外部遷移の検知→Back→警告→ログ）と 2（スケアウェア文言の検知と警告） |
| 対象端末 | 未定。API 29〜36 全般を対象とし、実機確認は人手検証（BL-009）とする |
| 利用者 | 子供が主目的だが、大人も広告対策として使う。利用モード（こども／おとな）を設ける（4章） |
| 実装形態 | 独立アプリとして新規作成（本リポジトリ）。言語は Kotlin |

### 1.2 前提の矛盾・見落とし

1. **「外部遷移は検知して戻す」の対象はアプリ間の遷移に限られる。** ブラウザ内でのページ遷移（同じブラウザの
   別タブ・リダイレクト）は前面パッケージが変わらないため、MVP では検知できない。ブラウザ内の悪質ページは
   スケアウェア文言の検知（優先順2）で拾う。
2. **「ユーザー操作の有無」で分岐しても、MVP では結論が同じになる。** PLAN 6章の条件
   `now - lastClickAt < 3s || ユーザー操作なし` は「クリックの直後」と「クリックなし」の両方をブロック対象とするため、
   実質的に「アプリから外部への遷移はすべて対象」となる。MVP では直前のクリック有無を**ログに残す情報**として扱い、
   判定には使わない。誤ブロックは除外リストと利用モードで抑える（5章）。
3. **大人の利用が前提から抜けていた。** 子供向けの自動 Back とひらがなの文言は、大人には過剰になる。
   利用モードを要件に加えた（4章）。
4. **Android 16 以降の「高度な保護（Advanced Protection）」を有効にした端末では、本アプリは動かない見込み。**
   アクセシビリティ API の利用が `isAccessibilityTool` を宣言した支援技術アプリに限られるためで、本アプリは
   支援技術ではないため宣言してはならない（Google の定義に反する）。要実機確認。
5. **広告画面の判定（優先順3）が無い状態での外部遷移ブロックは、広告由来かどうかを区別しない。**
   ゲームアプリから Play ストアの正規のレビュー画面へ移る場合なども対象になる。こどもモードではこれを
   許容し（保護を優先）、おとなモードでは確認を出すだけにする。

### 1.3 未確認のまま残す事項

- 命名の重複確認と旧仮名遣いの辞書確認（PLAN 2.3）は BL-010（人手検証）で扱う。
- 子供の端末の機種・OS バージョン、Family Link の利用有無は未定。

### 2.1 AccessibilityServiceInfo の設定

| 設定 | 値 | 理由 |
| --- | --- | --- |
| `accessibilityEventTypes` | `typeWindowStateChanged`・`typeWindowContentChanged`・`typeViewClicked` | 前面の変化、画面の文字の変化、直前のクリックの記録に必要な最小限 |
| `canRetrieveWindowContent` | `true` | スケアウェア文言の読み取りに必要 |
| `flagIncludeNotImportantViews` | 有効 | Web コンテンツの文字が「重要でない」ノードに入る場合があるため |
| `flagReportViewIds` | 無効 | MVP では ID を使わない。広告画面の判定（優先順3）で必要になったら有効にする |
| `canPerformGestures` | `false` | 代理タップ（優先順5）まで使わない。権限は最小にする |
| `notificationTimeout` | `200` | 文字の変化イベントの連打を間引く |
| `isAccessibilityTool` | 宣言しない | 支援技術ではないため |

### 2.2 バッテリー最適化・プロセス終了

- アクセシビリティサービスはシステムがバインドするため、通常はプロセスが終了されにくい。
- 一部の機種（独自の省電力機能を持つもの）では終了されることがある。README で「電池の最適化の対象外にする」
  手順を案内し、BL-009 で実機確認する。

## 3. 機能の実現可否の再評価（PLAN 4章への回答）

| 機能 | PLAN の評価 | 再評価 | 理由・実機でしか確かめられない点 |
| --- | --- | --- | --- |
| 前面アプリ/画面の検知 | ◎ | ◎ | `TYPE_WINDOW_STATE_CHANGED` の `packageName`。ただしキーボード・通知シェード・ダイアログも前面として通知されるため除外リストが要る |
| 広告画面の判定 | ○ | ○ | SDK の Activity 名は難読化・更新で変わる。MVP の範囲外 |
| 画面上の文字の読み取り | ○ | ○ | Chrome の Web コンテンツは多くの場合読めるが、Canvas 描画や一部のブラウザでは読めない（要実機確認） |
| ブラウザの URL 取得 | △ | △ | MVP では使わない |
| 警告バナー | ◎ | ◎ | `TYPE_ACCESSIBILITY_OVERLAY` は追加の権限が不要 |
| 大きな「戻る」ボタン | ◎ | ◎ | おとなモードの確認バナーとして MVP に含める |
| 外部遷移の検知とブロック | ○ | ○ | 戻した後に元のアプリが再び外部遷移を起こす「繰り返し」がありうる。クールダウンと連続回数の上限で抑える |
| ユーザー操作の有無の判別 | △ | △ | Web コンテンツ内のタップは `TYPE_VIEW_CLICKED` が出ないことがある（要実機確認）。MVP はログのみに使う |
| スケアウェア文言の警告 | ○ | ○ | 文言の照合は確実だが、正規の記事（ウイルスの解説記事等）でも反応する。誤検知は警告に留めることで影響を抑える |

## 4. 利用モード（大人の利用への対応）

広告対策は大人も使うため、利用者に合わせて介入の強さと文言を切り替えます。

| 項目 | こどもモード（既定） | おとなモード |
| --- | --- | --- |
| 外部遷移の検知時 | 自動で戻る（`GLOBAL_ACTION_BACK`）→ 警告バナー → ログ | 自動では戻らない。「戻る」「このまま進む」を出す → ログ |
| スケアウェア文言の検知時 | 警告バナー → ログ | 警告バナー → ログ |
| 文言 | ひらがな中心・怖がらせない（PLAN 2.5） | 通常の日本語で、検知理由を具体的に示す |
| モードの切替 | 設定画面から。PIN による保護は PIN 機能（BL-012）とあわせて追加する | 同左 |

- 既定を「こども」にするのは、PLAN の主目的が子供の保護であり、切替忘れでも保護が弱くならない側に倒すため。
- おとなモードでも検知とログは止めない。取りこぼしを生まずに、大人の意図した操作だけを妨げないようにする。

## 5. 誤ブロック対策（PLAN 8章 6）

- **遷移元の除外**: ランチャー（`MAIN/HOME` を解決するアプリ）、システム UI、設定、本アプリ、キーボード
  （IME）からの遷移は対象外。ブラウザ同士・同一アプリ内の遷移も対象外。
- **遷移先の限定**: ブラウザ（`VIEW https` を解決するアプリとルールの一覧）、Play ストア、パッケージ
  インストーラーへの遷移だけを対象にする。PLAN の「未知アプリ」は誤ブロックが多いため MVP では対象外とする。
- **繰り返しの上限**: 同じ遷移元から短時間（既定 30 秒）に外部遷移が繰り返された場合、自動で戻すのは一定回数
  （既定 3 回）までとし、それ以降は警告だけにする。正規のアプリと「戻る」を取り合い続けるのを防ぎつつ、
  1〜2回目の再遷移は止める（検知は `ExternalTransitionDetector` が回数を数え、介入の強さは利用モード側で決める）。
- **ブラウザからの遷移**: ブラウザ同士の移動は対象外。ブラウザからストア・インストーラーへの遷移は、
  悪質なページによる誘導がありうるため対象にする。ストア・インストーラーからの遷移は対象外。
- **おとなモード**: 自動で戻さず、利用者が選ぶ。
- **保護者 PIN による一時解除**: MVP の範囲外（BL-012）。

## 6. 検知ルールの更新方法（PLAN 8章 7）

- ルールは `mobile/src/main/assets/rules.json` に置き、アプリの更新で差し替える。
- 形式に `version` を持たせ、読み込みに失敗した場合はコード内の既定ルールで動かす（起動時検証と安全なフォールバック）。
- 文言は正規化（全角半角・大文字小文字の統一）してから部分一致で照合し、表記ゆれによる取りこぼしを減らす。
- SDK 名・Activity 名は難読化で変わるため、広告画面の判定（優先順3）ではクラス名より文言（「広告」「スキップ」等）を
  主に使う方針とする。外部ファイルからのルール取得（ネットワーク）は、改ざん対策が要るため MVP では行わない。

## 7. MVP の構成

### 7.1 構成図

```text
MimidukuAccessibilityService（AccessibilityService）
 ├─ onAccessibilityEvent
 │   ├─ WINDOW_STATE_CHANGED → ForegroundTracker へ前面パッケージを渡す
 │   │     └─ ExternalTransitionDetector が判定 → InterventionPolicy（利用モード別の介入）
 │   │           ├─ こども: GLOBAL_ACTION_BACK → 警告バナー → DetectionLog
 │   │           └─ おとな: 確認バナー（戻る／このまま進む）→ DetectionLog
 │   ├─ WINDOW_CONTENT_CHANGED → 間引き → ノードの文字を収集 → ScarewareMatcher
 │   │     └─ 一致 → 警告バナー → DetectionLog
 │   └─ VIEW_CLICKED → 直前のクリック時刻を記録（ログ用）
 └─ OverlayController（TYPE_ACCESSIBILITY_OVERLAY の View）

MainActivity（Compose）: サービスの状態、設定を開く、利用モード、制限された設定の手順、ログ件数
```

### 7.2 クラス一覧

| パッケージ | クラス | 役割 | Android 依存 |
| --- | --- | --- | --- |
| `rules` | `DetectionRules` / `RulesLoader` | ルールの型と JSON 読み込み（失敗時は既定値） | なし |
| `rules` | `ScarewareMatcher` | 文言の正規化と照合 | なし |
| `detect` | `ExternalTransitionDetector` | 前面パッケージの変化から外部遷移を判定 | なし |
| `mode` | `UsageMode` / `InterventionPolicy` | 利用モードと、モード別の介入内容 | なし |
| `mode` | `UsageModeStore` | 利用モードの保存（SharedPreferences） | あり |
| `log` | `DetectionLog` | 検知ログの保存（件数上限、一時ファイル＋置換） | なし（`File` のみ） |
| `service` | `MimidukuAccessibilityService` | イベントの受け取りと各部品の接続 | あり |
| `service` | `NodeTextCollector` | ノードツリーから文字を集める（件数・深さ上限つき） | あり |
| `overlay` | `OverlayController` | 警告・確認バナーの表示と自動消去 | あり |
| ルート | `MainActivity` | 設定画面 | あり |

### 7.3 権限

| 権限・宣言 | 用途 |
| --- | --- |
| `android.permission.BIND_ACCESSIBILITY_SERVICE`（サービスの `permission` 属性） | システムだけがサービスへバインドできるようにする |
| `<queries>`（`VIEW https`・`MAIN/HOME`） | ブラウザとランチャーの判別 |

`SYSTEM_ALERT_WINDOW`・`INTERNET`・`QUERY_ALL_PACKAGES`・`POST_NOTIFICATIONS` は使わない。

### 7.4 AndroidManifest と accessibility_service_config.xml の案

実ファイル（`mobile/src/main/AndroidManifest.xml`・`mobile/src/main/res/xml/accessibility_service_config.xml`）を正とする。
要点は次のとおり。

- サービスは `android:exported="true"`・`android:permission="android.permission.BIND_ACCESSIBILITY_SERVICE"`、
  `intent-filter` に `android.accessibilityservice.AccessibilityService`、`meta-data` で設定 XML を指す。
- 設定 XML は 2.1 の表のとおり。`android:description` に、読み取った画面の文字を保存・送信しないことを書く。

## 9. 実機テストの方針（PLAN 8章 8）

- 端末は少なくとも Android 10・13・14 以降の3世代。ジェスチャーナビと3ボタンナビの両方。
- 広告の再現には、実広告をクリックしない（クリック詐欺になるため）。代わりに次で再現する。
  - 外部遷移: `adb shell am start -a android.intent.action.VIEW -d https://example.com` を、任意のアプリを前面に
    出した状態で実行する（アプリからブラウザへの遷移として観測される）。Play ストアは `market://details?id=...`。
  - スケアウェア: 「ウイルスに感染しています」等の文言を含むローカルの HTML をブラウザで開く。
- 具体的な手順と記録欄は `docs/TESTING.md`（BL-008）に置く。

## 10. セキュリティ・プライバシー（PLAN 8章 9）

- 読み取った画面の文字は、照合のためにメモリ上で使うだけで、保存も送信もしない。
- ログに残すのは日時・遷移元/遷移先のパッケージ名・検知種別・一致したルール ID・介入の内容・直前のクリックの有無のみ。
- ネットワーク権限を持たない（`INTERNET` を宣言しない）ことで、外部送信が構造的に起きないようにする。
- ログはアプリ内ストレージ（他アプリから読めない）に置き、`allowBackup="false"` でバックアップへ含めない。

## 11. キャラクター表示（PLAN 8章 10）

- みみづくバッジ（常駐表示・表情の切り替え）は MVP の範囲外（優先順7、BL-012）。
- 警告文言は MVP で文字列リソースへ分け、こども向けとおとな向けを別の文字列にする。キャラクターの名前
  （「みみづくが気づいたよ」）はこども向けの文言でだけ使う。

## 12. 優先順位の再提案（PLAN 8章 4）

初期案の順序は妥当。次の2点だけ変更を提案する。

1. 利用モード（4章）を優先順1・2と同時に入れる（介入の強さが利用者で変わるため、後から入れると判定の作り直しになる）。
2. 保護者 PIN（優先順6）は、こどもモードからおとなモードへの切替を守る用途があるため、広告画面の判定（優先順3）より先に
   着手することを推奨する。判断は BL-012 でユーザーが行う。
